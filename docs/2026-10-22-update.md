# CCLDL ladies dashboard update — 22 October 2026

This updates the existing white/pink committee application. The unrelated CCDL
mockup is excluded. Existing data, names, fixtures and photos are not rewritten.

## Changes

- Cup standings recalculate approved results using 2 points for a win, 1 for a
  draw and 0 for a loss, with P/W/D/L/legs for/legs against/points. League scoring
  remains games won. All teams present in the season's fixtures appear, including
  teams without results. No additional tie-break rule is introduced.
- Player statistics combine approved League and Cup results for the selected
  season/cutoff using player IDs. Double 1 counts accumulate, while scores and
  checkouts use each player's maximum. Correcting an existing result replaces its
  contribution. Additional individual scores/checkouts can be retained in result
  JSON and viewed in the match summary.
- Mobile fixture search, 44px controls, readable inputs, contained tables and
  repaired fixture-card overflow. Home wins still calculate away wins automatically.
- Weekly PNG: full League and Cup tables, five players per award, joint positions,
  larger type and 2160px-wide output. A taller single image is the default; the
  content selector also allows separate tables and player-leaders images. Ties at
  the fifth row are ordered by name/ID, with all players retained in dashboard lists.
- Local experimental OCR: whole-photo or adjustable cropped-region reading,
  editable text, explicit saved-player matching, repeated Double 1 readings,
  missing-value checks, review confirmation and manual fallback. Existing private
  originals can be read again without creating another photo. Applying readings
  replaces the pending form achievements; it does not approve/save automatically.
- Existing private archive, team/date/competition filters, correction audit and
  original-photo retention remain. A read-only historical review query is provided.

## Data and rollback

No database migration or live import is required or performed. Optional reading
arrays and reviewed OCR text use the existing summary JSON. No existing player,
result, fixture or original photograph is deleted or renamed. Database regression
checks exercise migrations/RLS, approvals, corrections, audit history and original
photo protection in an isolated database; they do not verify live records.

A recoverable live backup has not been verified in this session. Before any later
database changes, follow `supabase/BACKUPS.md` and test restoration separately.

## Scanner accuracy and costs

Four previously supplied handwritten League photos were evaluated with local
Tesseract. Its reported OCR confidence was only 35–42% (not a measured field
accuracy), and sheet identification was unreliable. This is a review-assisted
experimental tool, not a completed automatic handwriting scanner. Printed synthetic
League and Cup samples verify the workflow, not real Cup handwriting accuracy.

Names, dates, totals, crossed-out writing and extra handwritten notes must be
checked against the photo. Individual game/player rows are not reliably converted
into structured results; normal manual entry remains available. No actual Cup
photo was available for a handwriting test. No missing historical finishes are
invented. The supplied read-only query can help locate results needing review,
but only comparison with originals can find omitted handwritten statistics.

No paid API, subscription or external OCR provider is added. OCR runs on the
committee member's device using locally hosted assets. Existing Railway/Supabase
hosting, storage and bandwidth remain subject to their existing plan limits.
